## Architecture

The library models "noisy values" — observations paired with a symbolic posterior over their true value — using SymPy for symbolic math and NumPy/SciPy for sampling.

### Core abstractions (`src/core.py`)

**`Node`** is the fundamental unit. Every noisy value is backed by a DAG of `Node` objects, each holding:
- `role`: `"latent"` (unknown true parameter), `"noise"` (random variable with a known distribution), or `"derived"` (algebraic combination)
- `symbol`: a unique SymPy `Symbol` auto-generated by `util.fresh_name()`
- `source`: a `NoiseSource` instance (for noise nodes); can reference other node symbols as parameters for hierarchical/dependent noise
- `constraints`: equations that pin latent symbols (e.g., `obs = theta + eps`)
- `deps`: parent nodes, forming the DAG

**`NoisyValue`** wraps a `(obs, root_node)` pair. Subclasses enforce the observed type:
- `NoisyFloat` — real-valued observations; supports arithmetic, exp/log/sqrt, rounding
- `NoisyInt` — integer observations; supports constructor helpers like `NoisyInt.binomial(...)`
- `NoisyBool` — boolean observations; supports `&`, `|`, `~`
- `NoisyNumber` — shared numeric base (comparison operators that return `NoisyBool`, `guarded()`)

Arithmetic operators on `NoisyValue` subclasses call `bin_op` / `unary_op`, which compose both the observed scalar and the symbolic expression in tandem.

**`NoisyValueSampler`** (returned by `noisy_value_sampler()`) does the heavy lifting:
1. Collects all latent symbols and constraints across a joint set of values
2. Solves latent symbols symbolically via `sympy.solve` (static substitutions, computed once)
3. Separates noise nodes into *independent* (no `deps`) and *dependent* (hierarchical)
4. On each `.sample(n)` call, bulk-samples all independent noise via NumPy, then resolves dependent nodes in topological order using `source.instantiate(resolved).sample(rng)`, then evaluates expressions via `sp.lambdify`
5. Returns a `SampleBatch` wrapping a 1-D NumPy array

### Supporting modules

- **`src/noise.py`** — `NoiseSource` base class and two concrete subclasses: `NormalNoiseSource`, `BinomialNoiseSource`. Each implements `free_symbols` (SymPy symbols its parameters depend on), `instantiate(resolved)` (substitutes resolved values into parameters), `sample(rng, size)` (NumPy sampling), and `sympy_rv()` (returns a SymPy RV for visualization). Use the public constructors `gaussian(loc, scale)` and `binomial(n, p)` — parameters can be plain numbers, SymPy expressions, or `NoisyFloat`/`NoisyInt` values.
- **`src/analysis.py`** — `NoisyContingencyTable` wraps a 2-D array of `NoisyNumber`s and provides `chi_squared()`, `odds_ratio()`, and `with_stratified_sampling_uncertainty()` (the last one adds binomial sampling uncertainty row-by-row, which is the key differential-privacy use case). Also exposes `noisy_min` / `noisy_max`.
- **`src/array.py`** — `float_array_sampler` / `sample_float_array` for sampling tensor-shaped collections of noisy values jointly.
- **`src/visual.py`** — `plot_posterior()` renders posterior densities deterministically via tensor-product Gauss-Legendre quadrature in quantile space (no Monte Carlo), then weighted KDE. Uses `source.sympy_rv()` to get quantile functions for each noise source. Requires `matplotlib` (dev dependency).
- **`src/util.py`** — `fresh_name()` / `reset_name_provider()` for globally unique SymPy symbol names. Tests call `reset_name_provider()` via `conftest.py` to avoid symbol collisions.
- **`src/census.py`** — the 2020 Census PL94-171 and DHC-person Noisy Measurement File releases, expressed as `dataset`-framework products (see below): a declarative schema (`Axis`/`Measurement`/`GeoLevel` literals for `PL94_PERSON`, `PL94_UNIT`, `DHC_PERSON`), an `NmfSource` for the Hive-partitioned parquet layout in `data/2020-pl94-nmf-parquets`/`data/2020-dhc-nmf-parquets` (scanned lazily via polars with partition pruning), and evidence rules (`pl94_person_evidence`, `pl94_unit_evidence`, `dhc_person_evidence`) that translate each release's native constraint rows (`total_con`, `nurse_nva_0_con`, `hhgq_total_lb_con`/`_ub_con`, `pl94_con`, the `relgqN_..._con` age rules) into the framework's dataset-agnostic evidence vocabulary. `pl94_2020` / `pl94_2020_units` / `dhc_2020` are the resulting `Product` objects; `pl94_2020.view(...)` / `dhc_2020.view(...)` open a `View` whose cells are resolved once and shared, so two queries against the same view stay jointly consistent (e.g. `sex*hispanic` and `sex*age_38_groups` against one DHC view share the `pl94_con` invariant that ties them together). `get_pl94()` / `get_dhc()` are thin wrappers around a throwaway view — one call, one independent view, tidy pandas DataFrames whose `value` column is a `NoisyIntArray` of (possibly truncated) discrete-Gaussian posteriors. Geocodes are DAS spine codes: standard GEOIDs are derived for every level except block groups (spine "optimized block groups" ≠ tabulation block groups; `get_pl94(..., real_block_groups=True)` recovers real ones by re-aggregating from blocks); the spine also splits states into non-AIAN/AIAN branches (`aian` column). The codebook orderings (cenrace 63 combos, hhgq 8 levels, the DHC-P relgq/age orderings recovered from the national file itself, etc.) were validated against published 2020 tabulations in `test/test_census.py`. `pl94_queries()` / `dhc_queries()` tabulate the available queries, and `fetch_dhc(geography, state=..., county=...)` mirrors just the DHC partitions asked for from the public Census S3 bucket (about 1.5 MB per state, 1.8 MB per county) — that release is not bundled. `dhc_table_variables()` / `unsupported_dhc_table_variables()` crosswalk literal `tidycensus`-style variable codes (e.g. `"P12_002N"`) onto `get_dhc` query/axis-filter combinations, for table P12 ("Sex by Age") so far.

  The block-level construction that conditions DHC cells on the exact PL94 invariant — splitting a query's cells into blocks of known total, merging each axis only as far as PL94 resolves it (sex always merges, since PL94 has no sex), and building the 0/1/2/3+-free-cell ladder (empty / point mass / anti-correlated pair / bound-only) — is generic and lives in `dataset/solve.py` and `dataset/partition.py`, not in `census.py`; `census.py` only supplies the evidence translation. See `docs/dataset-framework.md` for the full design rationale and `dataset/__init__.py` for the framework itself.

- **`src/wikimedia.py`** — the Wikimedia differentially-private pageview releases (daily counts per country, project, and page since July 2015). `fetch_pageviews(days)` mirrors the public daily TSVs into `data/wikimedia-pageviews` (~6 MB/day historical, ~25–60 MB/day current; nothing bundled or fetched implicitly; `days_between` builds ranges and skips the five never-released days); `get_pageviews(days, country=..., project=..., page=..., ...)` returns a tidy DataFrame whose `value` column is a `NoisyIntArray` of nonnegative flat-prior posteriors. The module's core is a codebook that routes each row to the mechanism that noised it: three eras (geometric scale 300 then 30; discrete Gaussian with σ²=10/(2ρ) by country risk tier since Feb 2023), seven patch days and an *intermittent* US gap (178 of 226 days) backfilled with the geometric mechanism, dated protection-list revisions (2024-02-15, 2024-05-19, 2026-01-26), and Turkey's undocumented blanket exclusion. Every constant was derived or validated empirically from the released files (a country's minimum released count reveals its threshold, hence its mechanism); live tests in `test/test_wikimedia.py` re-check them but skip unless the probe days are mirrored (the fetch call is in that file's integration-section comment). Cell noise symbols are derived from row identity via `LatticeFamily.cell(symbol=...)`, so — unlike `census.py` — repeated reads of one cell are the same random variable. Caveats that matter downstream: counts are deduplicated and clipped (first 10 unique views per device in the current era), the historical eras did not filter automated traffic (sums track the API's all-agents totals), and an absent row means the noisy count fell below the threshold, not zero — `missing="censored"` returns such requested-but-absent cells as posteriors encoding exactly that (refusing countries whose absence was policy, per `_PRE_TIERS_EXCLUDED`), built on `LatticeFamily.suppressed` and the `CensoredLatticeNode` types in `graph.py`. `docs/wikimedia-true-pageviews.md` holds design notes for going further, from these deduplicated clipped counts to posteriors over actual pageviews. `example/wikimedia_pageviews.ipynb` is the walkthrough, and `docs/wikimedia-errata.md` records every observed departure from Wikimedia's own documentation; `CODEBOOK_AS_OF` marks how far the vendored constants are validated, and the loaders warn beyond it.

### Key design constraint

Every `NoisyValue` carries its full probabilistic provenance in the Node DAG. Sampling is always *joint*: shared nodes (same `symbol`) are sampled once per draw and reused, so correlated values stay correlated. This is essential for the differential-privacy contingency table use case where row marginals must be consistent.
